# Rubric: is this plan ready to post and build from?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| fix-rationale | The plan's stated diagnosis and proposed implementation approach, read against the accepted repro-evidence block's reproduction steps, inputs, and observed result. | Pass if the diagnosis is consistent with the reproduced observations and gives a plausible mechanism for the observed failure, and the proposed change directly addresses that mechanism. Fail if the diagnosis contradicts a reproduced observation, does not explain the reproduced failure, or the proposed change only hides or bypasses the symptom instead of addressing the stated mechanism. | required |
| scope-bounded | The plan's scope statement, proposed files or areas, and stated in-scope and out-of-scope work, read against the issue context and accepted repro evidence. | Pass if the plan proposes one bounded change needed to address the reproduced issue, without unrelated cleanup, redesign, refactoring, or additional features. Fail if the proposed work expands beyond what is needed for the issue by including unrelated cleanup, redesign, refactoring, or additional features. | required |
| execution-ready | The plan's identified files or areas, implementation approach, and order of work. | Pass if a contributor who did not write the plan could identify where to begin and what behavior to change without inventing a major missing implementation strategy. Fail if a contributor would have to determine the core approach or invent a major missing implementation step before starting. | required |
| uncertainty-honest | The plan's stated risks, assumptions, unknowns, and any recorded deviations, read against what the issue context and repro evidence actually establish. | Pass if any material unresolved question or assumption that could affect the plan's scope, implementation approach, or verification is identified as uncertainty rather than presented as established fact, and any known deviation from the plan is stated explicitly. If no such material uncertainty or deviation is present, the check may still pass. A diagnosis is not an unresolved assumption merely because its internal mechanism is inferred from repro evidence rather than directly proven. Fail if a material unresolved question or assumption that could affect the planned work is presented as certain, or a known deviation that affects the planned work is concealed. | required |
| verification-plan | The plan's test plan, read against the accepted repro-evidence block's reproduction steps, inputs, and observable failing result. | Pass if the plan states how the relevant behavior will be checked after implementation and names an observable expected result that would distinguish the fixed behavior from the reproduced failure. Fail if the proposed check would not exercise the relevant behavior, or if it gives no observable result that distinguishes success from the reproduced failure. | required |
| comment-aligned | The candidate plan comment, read against the candidate plan, the issue and thread highlights, and the repo-facts block, including any stated contribution, communication, or AI-disclosure requirements. | Pass if the comment does not materially misstate the planned change, respects relevant thread constraints, and satisfies every applicable repository-stated requirement for the comment. If the repo facts require AI-use disclosure for issues or comments, the candidate comment must include that disclosure. Fail if the comment materially misrepresents the plan, ignores or contradicts relevant thread direction, violates an applicable repository-stated requirement, or omits a required AI-use disclosure. | required |

## Verdict rule

Accept only if every required check passes. Reject if any required check fails or is unclear. Unclear counts as fail for the final verdict. Preferred checks never change the verdict.
